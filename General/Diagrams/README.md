## Overview

This document explains the meaning of the different relationship line styles used in the **ER Diagram generated by DBeaver**. DBeaver visually represents table relationships using **continuous (solid)** and **dotted** lines, each with a specific meaning regarding how tables are linked in the database.

---

## Line Types in DBeaver ER Diagram

### 1. Continuous (Solid) Line – Identifying Relationship

A **continuous line** indicates an **identifying relationship** between two tables.

This means:
- The **foreign key is part of the child table’s primary key**
- The child table **cannot be uniquely identified without the parent**
- This usually represents a **weak entity**

**Key point:**  
The child table depends on the parent for its identity.

---

### 2. Dotted Line – Non-Identifying Relationship

A **dotted line** represents a **non-identifying relationship**.

This means:
- The **foreign key is not part of the child table’s primary key**
- The child table **can exist independently**
- This is the most commonly used relationship

The child exists independently of the parent’s identity.

---

## Quick Summary

| Line Style | Relationship Type     | Foreign Key in Primary Key |
|----------|---------------------------|-----------------------------|
| Solid    | Identifying Relationship | ✅ Yes                      |
| Dotted   | Non-identifying          | ❌ No                       |

---

## Why this matters

Understanding these differences helps in:
- Designing proper database schemas
- Preventing incorrect normalization
- Understanding dependent vs independent tables
- Designing composite keys correctly
